# Разработка и приёмка

Проект использует стандарт 0.4.0 и профили: infra, service. Прочитай [полные правила](../../.standards/rules.ru.md). Пакет подключает проверки и не доказывает соответствие всего прежнего кода, переводов и runtime-сценариев.

Управляющий репозиторий приватный. Распространяется только разрешённый состав tools/export.mjs. Реестр, клиентские материалы, локальные пути и эксплуатационные заметки не попадают в публичные проекты. Копия пакета работает в PR из форка без доступа к приватному источнику.

## Область и первый этап

Создай ветку от проверенного текущего commit основной ветки. Прочитай AGENTS.md, существующие hooks и CI. Добавь автономную .standards, .repo-policy.json, отдельный workflow, development-standard.md двух языков и актуальные правки README. Сохрани родные проверки форматирования, сборки и выпуска. Укажи реальные пути языковых README без слепого переименования. До подтверждения всех применимых доказательств оставь adoption: adopting.

Первое подключение проверяет форматирование изменённых файлов, секреты добавляемых коммитов, наличие языковых файлов и strict docs-policy. Полная история, качество презентации, перевод старой документации, форматирование всех файлов и профильная приёмка учитываются отдельно. Общий job не подтверждает их выполнение.

## Локальная подготовка

Выполни команды из корня репозитория. Нужны Git, Node.js 22 или новее, npm, tar и POSIX shell:

```sh
npm ci --prefix .standards --ignore-scripts --no-audit --no-fund
node .standards/install-gitleaks.mjs
node .standards/install-hooks.mjs
node .standards/check.mjs structure
```

Hook читает индекс Git и не перезаписывает файлы или staging. Предыдущий hook запускается первым и сохраняется. Прежний hooksPath записывается локально. При нескольких worktree используется ручное подключение к существующему hook, чтобы неожиданно не менять общие настройки. Для pre-commit добавь local hook с node .standards/check.mjs staged и pass_filenames: false; два конкурирующих менеджера hooks не устанавливаются.

Для отката восстанови прежний hooksPath из локального repository-standard-hook.json. Если он был пустым, удали локальную настройку core.hooksPath. Исходный hook сохраняется. Удаление подключения выполняется проверяемым PR; история и прежние проверки продукта остаются.

## CI и защита слияния

Job repository-standard проверяет полный diff PR относительно merge base, включая очередь слияний. Нужны содержательные изменения обоих README и Markdown в обоих каталогах документации. Пробелы, комментарии и удаление не засчитываются. Смысл изменений и качество перевода проверяет ревью. Pre-commit сообщает о недостающей документации, но не доказывает будущий merge.

Делай repository-standard обязательным только после появления workflow в основной ветке и его успешного реального запуска. Сохрани все прежние required checks. Проверь фактическое правило хостинга и права обхода; ограничения тарифа фиксируются отдельно. Наличие YAML не доказывает запрет слияния. Действующее правило о merge владельцем сохраняется.

## Исходная проверка форки и обновления

Полный Gitleaks по истории - отдельный этап первичного подключения и private-to-public. Запускай его в разрешённом изолированном checkout с маскировкой отчётов. Опубликованный секрет сначала отзывается. Точные зеркала и архивы учитываются приватным реестром без внедрения файлов и реактивации. Форки с изменениями сохраняют правила и авторство upstream.

Обновление пакета приходит отдельным версионированным PR. Проверь все суммы lock, изменения правил и workflow, отрицательные тесты; отделяй доказательства продукта от подключения инструмента. Сгенерированные правила строятся из двуязычного каталога; исправляй его, а не один язык результата.

## Запись приёмки

Сохраняй commit/digest, среду, команду, дату и результат для CI, чистого bootstrap, релиза/установки/обновления, runtime, полной истории, общего форматирования, презентации и профилей. PASS требует доказательства, NOT_APPLICABLE - причины. NOT_VERIFIED остаётся видимым и не выдаётся за соответствие.
